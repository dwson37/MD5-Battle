📘 해시 배움터

🤔 해시(Hash)란?

해시 함수는 어떤 데이터를 넣든 정해진 길이의 값을 돌려주는 함수예요. 이렇게 나온 값을 해시값 또는 다이제스트(digest, 요약)라고 불러요. 영어 hash는 '잘게 다지다'라는 뜻이에요. 데이터를 잘게 다지고 마구 섞어서 짧은 값으로 만든다는 의미죠.

🍹 믹서기 비유
딸기와 바나나를 갈면 주스가 돼요. 같은 재료를 같은 만큼 넣으면 언제나 똑같은 주스가 나오지만, 주스만 보고 원래 과일을 되살릴 수는 없어요. 해시 함수도 이와 비슷해요.
🖐️ 지문 비유
사람마다 지문이 다르듯 데이터마다 해시값이 (거의) 다 달라요. 그래서 커다란 파일 두 개를 처음부터 끝까지 비교하지 않고 해시값만 비교해도 같은지 다른지 빠르게 알 수 있어요.

MD5 결과를 직접 보자

입력이 한 글자든, 아무것도 없든, 아주 긴 문장이든 결과는 언제나 16진수 32자리(= 128비트)예요.

MD5는 누가 만들었을까?

MD5(Message-Digest Algorithm 5)는 1991년 MIT의 암호학자 로널드 라이베스트(Ronald Rivest)가 설계했고, 1992년 인터넷 표준 문서 RFC 1321로 공개되었어요. 라이베스트는 유명한 공개키 암호 RSA의 'R'이기도 해요. 앞서 만든 MD4를 더 튼튼하게 고친 것이 MD5예요.

이 게임은 해시를 어떻게 쓸까?

입력한 문자열 → UTF-8 바이트로 바꾸기 → MD5 계산 → 32자리를 4자리씩 8조각 → 조각마다 체력·공격력 같은 능력치가 돼요. 자세한 내용은 에서 볼 수 있어요.

🔢 16진수 읽는 법

우리가 평소에 쓰는 10진수는 0~9 열 개의 숫자를 써요. 16진수는 0~9에 a, b, c, d, e, f를 더해 열여섯 개의 기호를 써요.

16진수 한 자리는 0~15를 나타내는데, 이것은 2진수 4자리(4비트)와 딱 맞아요. 예: f = 15 = 1111₂. 그래서 MD5의 32자리 = 32 × 4 = 128비트예요.

자리값 계산

10진수가 1, 10, 100, 1000의 자리를 쓰듯 16진수는 1, 16, 256, 4096의 자리를 써요. (16⁰, 16¹, 16², 16³)

4자리로 만들 수 있는 가장 큰 수는 ffff = 15×4096 + 15×256 + 15×16 + 15 = 65535예요. 그래서 이 게임의 조각 하나는 0~65535 사이의 값이 돼요.

MD5로 나올 수 있는 값은 모두 몇 가지?

32자리 각각에 16가지 기호가 올 수 있으니 1632 = 2128가지예요.

2^128 = 340,282,366,920,938,463,463,374,607,431,768,211,456 ≈ 3.4 × 10^38 (약 340간)

지구의 모든 해변 모래알은 약 1018~1019개로 추정되니, 그보다도 1019배 이상 많은 수예요!

🧬 좋은 해시 함수의 성질

🎯 결정성

같은 입력은 언제, 어디서, 몇 번을 계산해도 항상 같은 출력이 나와요. 이 게임에서 같은 이름이 언제나 같은 캐릭터가 되는 이유예요.

📏 고정 길이

입력 길이와 상관없이 출력 길이가 같아요. MD5는 언제나 128비트(16진수 32자리)예요.

🌊 눈사태 효과

입력이 아주 조금만 달라져도 출력 비트의 약 절반이 바뀌어요. 그래서 비슷한 이름이라도 능력치는 전혀 비슷하지 않아요.

🚪 일방향성

해시값만 보고 원래 입력을 알아내는 것은 사실상 불가능해야 해요. 이를 역상 저항성이라고 해요.

🧩 충돌 저항성

해시값이 같은 서로 다른 두 입력을 찾기가 매우 어려워야 해요. ⚠️ MD5는 이 성질이 깨졌어요!

⚡ 빠른 계산

큰 파일도 금방 계산할 수 있어야 해요. 다만 비밀번호 저장에서는 빠른 것이 오히려 약점이 돼요.

🐦 충돌은 반드시 존재해요: 비둘기집 원리

비둘기 10마리가 비둘기집 9칸에 들어가면 적어도 한 칸에는 두 마리 이상이 들어가요. 해시 함수의 입력은 끝없이 많지만 출력은 2128가지뿐이니, 해시값이 같은 서로 다른 입력(충돌)은 반드시 존재해요. 그래서 좋은 해시 함수는 충돌이 없는 함수가 아니라, 충돌을 찾기가 너무 어려운 함수예요.

세 가지 저항성 정리

성질의미무작정 시도하면MD5의 현재 상태
역상 저항성해시값 h만 보고 md5(x) = h인 x 찾기약 2128번✅ 실용적인 공격 없음 (이론상 2123.4)
제2역상 저항성x가 주어졌을 때 md5(y) = md5(x)인 다른 y 찾기약 2128번✅ 실용적인 공격 없음
충돌 저항성md5(x) = md5(y)인 아무 쌍 x ≠ y 찾기약 264번 (생일 역설)❌ 깨짐: 일반 PC로 몇 초

충돌 찾기가 264번밖에 안 되는 이유는 에서 확인하세요.

분홍 칸 = 128비트 중 서로 다른 비트. 해시가 잘 섞는다면 평균적으로 약 64비트(50%)가 달라요.

🧱 컴퓨터가 실제로 해시하는 것: UTF-8 바이트 (입력 A)

MD5는 글자가 아니라 바이트(8비트 숫자)를 계산해요. 글자는 UTF-8 방식으로 바이트로 바뀌는데, 영어·숫자·기호는 1바이트, 한글은 3바이트, 이모지는 보통 4바이트예요. (␣ = 공백)

📦 패딩: 64바이트 블록 맞추기 (입력 A)

MD5는 데이터를 512비트(64바이트) 블록 단위로 처리해요. 길이를 딱 맞추기 위해 뒤에 내용을 덧붙이는데, 이것을 패딩(padding)이라고 해요.

원래 메시지 80 = 끝 표시(비트 1 다음 0 일곱 개) 00 채우기 원래 길이(비트 수, 8바이트)

🎮 게임 속 해시

1단계: 해시값을 8조각으로

MD5 32자리를 앞에서부터 4자리씩 끊으면 8조각이 돼요. 각 조각은 0~65535 사이의 수예요.

2단계: 조각을 능력치로 바꾸기

능력치 = 최솟값 + ⌊ 조각값 × (최댓값 − 최솟값 + 1) ÷ 65536 ⌋

조각값을 0 이상 1 미만의 비율(조각값 ÷ 65536)로 바꾼 뒤 능력치 범위만큼 늘리는 비례 변환이에요. ⌊ ⌋는 소수점 아래를 버린다는 뜻이에요.

속성만은 나머지 연산을 써요. 조각값 mod 3이 0이면 🔥불, 1이면 💧물, 2이면 🌿풀이에요. (mod = 나눈 나머지)

3단계: 장비 정하기

공격력과 방어력 범위를 5등급으로 나눠 무기와 방어구를 정해요.

⚔️ 전투 규칙

  • 1합 = 두 캐릭터가 한 번씩 공격하는 것
  • 선공: 속도가 높은 쪽이 먼저 공격해요. 속도가 같으면 왼쪽이 먼저예요.
  • 회피: 난수 < 상대의 회피율이면 MISS!
  • 기본 데미지 = 공격력 × 100 ÷ (100 + 상대 방어력)
  • 난수 보정: × 0.90 ~ 1.10
  • 필살기: 난수 < 행운 ÷ 500 이면 × 2 (행운 99 → 약 19.8%)
  • 치명타: 난수 < 치명타율이면 × 1.5 (필살기와 겹치면 × 3!)
  • 상성: 🔥불 → 🌿풀 → 💧물 → 🔥불 (화살표 방향으로 유리). 유리 × 1.2, 불리 × 0.8
  • 최종 데미지는 반올림하고, 최소 1이에요.
  • 체력이 0이 되면 KO! 50합이 지나도 끝나지 않으면 남은 체력 비율이 높은 쪽이 판정승이에요. (같으면 무승부)
데미지 = 반올림( 공격력 × 100 ÷ (100 + 방어력) × 난수보정 × 필살기 × 치명타 × 상성 )

🎲 '무작위'인데 왜 결과가 항상 같을까? 시드와 의사난수

컴퓨터는 진짜 무작위를 만들기 어려워서, 수식으로 무작위처럼 보이는 수를 만들어요. 이것을 의사난수(pseudo-random number)라고 하고, 처음에 넣어 주는 값을 시드(seed, 씨앗값)라고 해요. 시드가 같으면 나오는 수열도 언제나 같아요.

시드 = MD5( 두 해시 중 작은 것 + 큰 것 ) ← 이어 붙여서 한 번 더 해시! 난수 생성기 = sfc32 (시드 32자리를 8자리씩 4조각으로 나눠 넣고, 12번 미리 돌려 섞음)

두 해시를 크기 순서로 정렬해 이어 붙이므로 좌우를 바꿔도 시드가 같아요. 그래서 같은 두 문자열의 대결은 어느 컴퓨터에서 몇 번을 해도 결과가 같아요. 이렇게 같은 입력에 항상 같은 결과가 나오는 성질을 결정론적(deterministic)이라고 해요. (단, 두 캐릭터의 속도가 같을 때는 왼쪽이 먼저 공격하므로 좌우를 바꾸면 결과가 달라질 수 있어요.)

공격 한 번마다 난수를 4개씩 회피 → 난수보정 → 필살기 → 치명타 순서로 뽑아요. 대결이 끝난 뒤 📜 전체 전투 기록에서 모든 계산을 확인할 수 있어요.

🌍 해시는 어디에 쓰일까?

📥 파일 무결성 확인

프로그램 배포 사이트가 공개한 해시값과 내가 내려받은 파일의 해시값을 비교해요. 같으면 파일이 손상되거나 바뀌지 않았다는 뜻이에요.

🔑 비밀번호 저장

서버는 비밀번호 자체가 아니라 해시값을 저장해요. 로그인할 때 입력한 비밀번호를 해시해서 저장된 값과 비교하죠. (단, MD5로는 안 돼요! → 🔐 탭)

🗂️ 중복 파일 찾기

클라우드 저장소나 사진 정리 앱은 해시값으로 똑같은 파일을 찾아서 한 번만 저장해요.

🌳 Git 버전 관리

코드를 저장(커밋)할 때마다 그 내용의 해시값을 이름표로 붙여요. 원래 SHA-1을 썼고 SHA-256으로 옮겨 가는 중이에요.

⛓️ 블록체인

각 블록이 이전 블록의 해시값을 담고 있어 사슬처럼 연결돼요. 중간 블록 하나를 고치면 그 뒤의 해시가 모두 달라져서 바로 들통나요. 비트코인은 SHA-256을 써요.

✍️ 전자서명

긴 문서 전체 대신 문서의 해시값에 서명해요. 문서가 한 글자라도 바뀌면 해시가 달라져 서명이 맞지 않게 돼요.

📚 해시 테이블

이름 같은 키를 해시해서 저장 위치를 바로 계산하는 자료구조예요. 사전에서 단어를 순식간에 찾을 수 있게 해 줘요. (여기에는 보통 더 빠르고 간단한 해시 함수를 써요.)

🎮 이 게임처럼!

입력에서 골고루 퍼진 값을 뽑아내는 데도 써요. 프로필 기본 이미지(아이덴티콘), 게임 맵 자동 생성 같은 곳이에요.

🔐 MD5와 보안

⚠️ 결론부터: MD5는 이제 보안 목적으로 쓰면 안 돼요. 이 게임이나 실수로 생긴 파일 손상 확인처럼 보안과 상관없는 곳에서만 써요.

📅 MD5가 무너진 역사

  • 1991–1992 로널드 라이베스트가 MD5를 설계하고 RFC 1321로 공개
  • 1996 한스 도베르틴이 MD5 내부 압축 함수의 충돌을 발견해요. 전문가들이 다른 해시로 바꾸라고 권하기 시작했어요.
  • 2004 중국의 왕샤오윈(王小云) 연구팀이 실제 MD5 충돌 쌍을 발표해 전 세계 암호학계를 놀라게 했어요.
  • 2007 서로 다른 앞부분(접두사)을 가진 두 파일도 충돌하게 만드는 '선택 접두 충돌' 공격이 발표됐어요.
  • 2008 연구자들이 MD5 충돌로 인터넷 보안 인증 기관(CA)의 가짜 인증서를 만드는 데 성공했어요.
  • 2012 악성코드 '플레임(Flame)'이 MD5 충돌로 마이크로소프트의 코드 서명을 위조했어요.
  • 지금 일반 노트북으로도 몇 초 만에 MD5 충돌을 만들 수 있어요.

🔑 비밀번호를 MD5로 저장하면 안 되는 이유

🏎️ 너무 빨라요

MD5는 빠르게 계산하도록 설계됐어요. 최신 그래픽카드 한 장으로 1초에 수백억 개가 넘는 비밀번호 후보를 해시해 볼 수 있어서, 짧은 비밀번호는 금방 찾아내요.

📖 레인보우 테이블

흔한 비밀번호들의 해시값을 미리 계산해 둔 거대한 표예요. 예를 들어 는 인터넷에 검색만 해도 '123456'인 것이 바로 나와요.

🧂 해결책 ① 솔트

사용자마다 다른 무작위 문자열(솔트)을 비밀번호에 붙여서 해시해요. 같은 비밀번호도 해시값이 달라져서 미리 만든 표가 쓸모없어져요.

🐢 해결책 ② 일부러 느린 해시

bcrypt, scrypt, Argon2처럼 일부러 시간과 메모리를 많이 쓰도록 만든 비밀번호 전용 해시를 써요. 한 번은 금방이지만, 수십억 번 시도하기는 어렵게 만드는 거예요.

🧠 심화: 더 깊이 알아보기

⚙️ MD5 내부는 어떻게 돌아갈까?
  1. 바이트로 바꾸기: 문자열을 UTF-8 바이트로 바꿔요.
  2. 패딩: 끝에 비트 '1' 하나(바이트로는 80)를 붙이고, 전체 길이를 512로 나눈 나머지가 448비트가 될 때까지 0을 채워요. 마지막 64비트(8바이트)에는 원래 길이(비트 수)를 리틀 엔디언(작은 자리 바이트가 먼저)으로 적어요. →
  3. 블록 나누기: 512비트 블록마다 32비트 단어 16개 M[0]~M[15]로 쪼개요.
  4. 초깃값: 32비트 변수 4개로 시작해요.
    A = 67452301 B = efcdab89 C = 98badcfe D = 10325476
  5. 64단계 섞기: 블록마다 16단계씩 4라운드, 모두 64단계를 거쳐요. 라운드마다 다른 비트 함수를 써요.
    1라운드 F(B,C,D) = (B ∧ C) ∨ (¬B ∧ D) 2라운드 G(B,C,D) = (B ∧ D) ∨ (C ∧ ¬D) 3라운드 H(B,C,D) = B ⊕ C ⊕ D 4라운드 I(B,C,D) = C ⊕ (B ∨ ¬D) 한 단계: B ← B + ((A + f(B,C,D) + K[i] + M[g]) <<< s[i]) A ← D, D ← C, C ← (원래의) B ∧ AND ∨ OR ¬ NOT ⊕ XOR <<< 왼쪽으로 비트 회전 + 는 2^32로 나눈 나머지 덧셈
  6. 누적: 블록 하나가 끝나면 결과를 A, B, C, D에 더하고 다음 블록으로 넘어가요.
  7. 출력: 마지막 A‖B‖C‖D를 리틀 엔디언 바이트 순서로 이어 붙이면 128비트 해시값이 돼요.

상수 K[i] = ⌊ |sin(i+1)| × 232 ⌋. 사인값을 쓰는 이유는 설계자가 몰래 고른 수가 아니라는 것을 누구나 확인할 수 있게 하려는 거예요. 이런 상수를 'nothing-up-my-sleeve number(소매 속에 아무것도 없는 수)'라고 불러요.

🎂 생일 역설과 충돌 확률

한 반에 몇 명이 있으면 생일이 같은 두 사람이 있을 확률이 50%를 넘을까요? 정답은 겨우 23명이에요! 사람이 늘수록 비교할 '쌍'의 수는 n(n−1)/2로 빠르게 늘어나기 때문이에요.

해시도 똑같아요. 출력이 N가지일 때 약 √N번만 시도해도 충돌이 생길 확률이 꽤 높아져요. MD5는 N = 2128이니 √N = 264 ≈ 1.8 × 1019번이에요.

근사식: 충돌 확률 ≈ 1 − e−k(k−1) / (2N), k = 해시한 개수

264번도 엄청나게 많지만, 실제 MD5 공격은 내부 구조의 수학적 약점을 이용해 이보다 훨씬 빠르게(몇 초 만에) 충돌을 찾아요.

🔗 머클–담고르 구조와 길이 확장 공격

MD5는 블록을 하나씩 처리하면서 중간 결과(A, B, C, D)를 다음 블록으로 넘겨요. 이런 방식을 머클–담고르(Merkle–Damgård) 구조라고 하고, SHA-1과 SHA-256도 같은 구조예요.

그런데 해시값이 곧 '마지막 중간 상태'이기 때문에, md5(비밀 + 메시지)의 값과 길이만 알면 비밀을 몰라도 md5(비밀 + 메시지 + 패딩 + 덧붙인 내용)을 계산할 수 있어요. 이것을 길이 확장 공격이라고 해요. 그래서 메시지 인증에는 HMAC이라는 방식을 따로 써요. SHA-3은 스펀지 구조라 이 공격이 통하지 않아요.

🌈 레인보우 테이블은 어떻게 만들까?

모든 비밀번호의 해시값을 다 저장하면 표가 너무 커져요. 레인보우 테이블은 비밀번호 → 해시 → 환원 함수 → 새 비밀번호 후보 → 해시 → …로 이어지는 긴 사슬을 만들고, 사슬의 처음과 끝만 저장해요. 찾을 때는 사슬을 다시 따라가며 계산하죠. 저장 공간을 줄이는 대신 계산 시간을 조금 더 쓰는 '시간–공간 맞바꾸기' 기법이에요.

솔트를 쓰면 솔트마다 새 표가 필요해지기 때문에 레인보우 테이블은 사실상 쓸모가 없어져요.

🎲 이 게임의 의사난수 생성기 sfc32
function sfc32(a, b, c, d) { return () => { t = a + b + d; d = d + 1; // 카운터 a = b ^ (b >>> 9); b = c + (c << 3); c = (c <<< 21) + t; // 회전 후 더하기 return t ÷ 2^32; // 0 이상 1 미만 }; }

32비트 덧셈, 시프트, 회전만으로 만든 빠르고 품질 좋은 의사난수 생성기예요. 하지만 암호용은 아니에요. 암호처럼 예측되면 안 되는 곳에는 crypto.getRandomValues() 같은 암호학적으로 안전한 난수 생성기(CSPRNG)를 써야 해요.
